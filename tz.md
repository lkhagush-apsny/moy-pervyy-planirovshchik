# Техническое задание: «Моя неделя»

Версия: 1.1. Дата: 18 октября 2026 года.

## 1. Назначение и приоритет требований

Создать локальный планировщик рабочих и личных задач для одного пользователя на компьютере. Основной экран — недельная доска из семи дней. Продукт помогает распределять задачи, отмечать состояние работы, видеть процент завершения и переносить незавершённые задачи после подтверждения.

Это самостоятельное ТЗ для реализации. При расхождениях с `concept.md` использовать этот документ. В частности, «Обычный» заменён на «Средний», «Выполнено» — на «Готово», повторение ограничено выбранными днями недели. Термин «Высокий / Средний / Низкий» относится к приоритету, а не к статусу.

Текущий этап — описание продукта. Создание файлов приложения выполняется по отдельному запросу.

## 2. Поставка и технические ограничения

Готовое приложение состоит ровно из трёх файлов в одной папке:

| Файл | Ответственность |
| --- | --- |
| `index.html` | Семантическая разметка, подключение CSS и JS, контейнеры интерфейса |
| `style.css` | Все стили, состояния, адаптация к размеру настольного окна |
| `script.js` | Данные, логика дат, повторения, операции, события, отображение и сохранение |

- Запуск: двойной щелчок по `index.html`, адрес `file://`.
- Нативные HTML, CSS и JavaScript, без фреймворков, сборки, npm и установки пакетов.
- Скрипт подключить обычным `<script defer src="script.js">`, без ES-модулей, требующих серверного запуска.
- Без сервера, API, базы данных, сетевых запросов, CDN, внешних шрифтов, аналитики и облачной синхронизации.
- Для постоянного хранения использовать только localStorage. Экспортируемый JSON — пользовательская резервная копия.
- Иконки: встроенные SVG или CSS, без дополнительных файлов.
- Язык интерфейса — русский. Начало недели — понедельник. Даты и календарные переходы — по локальному времени компьютера.

### 2.1. Браузерная совместимость

Цель — работа во всех современных настольных браузерах, без привязки к Windows или одному производителю. Обязательная матрица проверки: актуальные стабильные Chrome, Edge, Firefox, Safari на macOS, Opera, Яндекс Браузер и Brave. Для остальных современных браузеров использовать стандартные возможности платформы и проверять наличие необходимых API, а не название браузера. Устаревшие версии и мобильный интерфейс не входят в объём первой версии.

Не обещать проверку буквально каждой существующей версии браузера. В отчёте реализации перечислить реальные версии, ОС и результаты; непроверенные сочетания явно обозначить. Ограничения доступа к localStorage при `file://` обрабатывать по разделу 10; отсутствие доступа не считать успешной проверкой полного функционала.

### 2.2. Организация кода

Сборку и дополнительные исходные файлы не вводить. Внутри `script.js` разделить код на логические модули с явными интерфейсами: календарь, валидация, хранилище, повторения, операции над задачами, отображение, формы и перетаскивание. Использовать функции и замыкания; бизнес-логика не обращается к DOM, отображение не записывает localStorage напрямую. Все изменения проходят через единый механизм проверки и сохранения. Число файлов не является основанием смешивать все обязанности в одной функции.

## 3. Пользователь и права

Единственный актор — владелец планировщика. Он может просматривать, создавать, редактировать, копировать, удалять, завершать и переносить любые задачи; управлять повторениями; экспортировать и заменять данные импортом.

Регистрации, входа, ролей администратора, разграничения прав и блокировки паролем нет. Любой человек, открывший страницу в том же профиле браузера, имеет те же возможности.

Автоматические действия приложения: восстановление данных, создание экземпляров повторений, расчёт прогресса, предложение переноса. Приложение не переносит незавершённые задачи без подтверждения.

## 4. Структура экрана

### 4.1. Панель управления

Содержит:

1. Название «Моя неделя».
2. Два явно подписанных диапазона с годом: «Текущая неделя: …» и «Просматриваемая неделя: …». Текущая календарная неделя видна постоянно, в том числе при просмотре прошлого или будущего. Когда диапазоны совпадают, допустима единая надпись «Текущая неделя: …».
3. Кнопки «Предыдущая неделя», «Сегодня», «Следующая неделя».
4. Основную кнопку «Добавить задачу».
5. Переключатель «Все / Работа / Личное».
6. Прогресс: полоса, целый процент и подпись «Готово X из Y».
7. Кнопку «Незавершённые задачи» с количеством подходящих задач прошлых недель.
8. Кнопку «Сначала важные».
9. Кнопки «Экспорт», «Импорт», «Хранилище и очистка» в компактном меню «Данные».
10. Неброскую надпись «Данные хранятся в этом браузере».

На каждом новом открытии показывается текущая неделя. Фильтр категории восстанавливается из настроек; при первом запуске — «Все». Кнопка «Сегодня» возвращает текущую неделю, сохраняя фильтр.

Строку с текущей неделей и навигацией закрепить при вертикальной прокрутке. При смене локальной даты обновлять диапазон текущей недели, не меняя просматриваемую неделю. Постоянная строка показывает даты текущей недели; вторая доска задач одновременно не выводится.

### 4.2. Недельная доска

- Семь колонок: Понедельник, Вторник, Среда, Четверг, Пятница, Суббота, Воскресенье.
- Заголовок: название дня, дата, количество карточек с учётом фильтра.
- Все дни равноправны; текущая дата выделена мягким фоном и рамкой.
- Кнопка «+ Задача» в каждом дне.
- Пустой день: «Нет задач»; если задачи скрыты фильтром: «Нет задач в этой категории».
- Доска имеет горизонтальную прокрутку при нехватке ширины; страница — общую вертикальную прокрутку. Избегать семи отдельных вертикальных областей прокрутки.
- Переход между неделями сдвигает выбранный понедельник ровно на семь календарных дней.

В DOM выводить только задачи просматриваемой недели и активной категории. Каждый день разбить на страницы по 50 карточек: при превышении лимита показывать «1–50 из N», «Назад» и «Далее» внутри колонки. Переключение недели или категории сбрасывает страницы к первым. После изменения числа задач ограничивать номер страницы последней доступной. Все счётчики, сортировка и прогресс используют полный набор задач, а не только видимые 50. Завершённые задачи не скрывать по статусу.

При действии «Показать» автоматически открыть страницу, содержащую нужную карточку. Для списка переноса также применять страницы по 50 строк; «Выбрать все» относится ко всему списку, выбор сохраняется между страницами. Не вводить виртуальный скроллинг в первую версию.

### 4.3. Карточка

Показывает название, до двух строк контекста, категорию с текстом и цветом, приоритет, статус, отметку «Готово», значок повторения при наличии серии и меню действий.

Полный текст открывается в редакторе. Длинные слова переносятся; название не выходит за границы. Завершённая карточка остаётся на своей позиции, название зачёркнуто; текст остаётся читаемым.

При переносе из другой даты показывать подпись «Перенесено с ДД.ММ.ГГГГ» по последнему перемещению с изменением даты. Полная история доступна в редакторе. Если повторение перенесено с его плановой даты, показывать также «Повторение за ДД.ММ.ГГГГ».

## 5. Данные задачи и формы

### 5.1. Поля и ограничения

| Поле | Правила | Значение при создании |
| --- | --- | --- |
| Название | Обязательно, 1–150 символов после обрезки внешних пробелов | Пустое |
| Контекст | Необязательно, до 1 000 символов; обычный текст, разрешены переносы строк | Пустое |
| Дата | Обязательная реальная календарная дата, годы 1900–2100 | См. ниже |
| Категория | «Работа» / «Личное» | «Работа» |
| Приоритет | «Высокий» / «Средний» / «Низкий» | «Средний» |
| Статус | «Не начато» / «В работе» / «Отложено» / «Готово» | «Не начато» |
| Повторение | Выключено либо выбранные дни недели | Выключено |

Длина строк измеряется количеством кодовых точек Unicode. Валидация одинакова в форме и импорте. Контекст сохраняется с переносами строк; внешние пробелы обрезаются. HTML и Markdown не интерпретируются.

Дата общей кнопки добавления: сегодня, если открыта текущая неделя; иначе понедельник открытой недели. Кнопка внутри дня устанавливает дату этого дня. Категория по умолчанию всегда «Работа», даже при фильтре «Личное»; пользователь может изменить её до сохранения.

### 5.2. Создание и редактирование

- Открывать модальное окно с подписями полей и кнопками «Сохранить» / «Отмена».
- При ошибках показать сообщение возле соответствующего поля, перевести фокус на первое неверное поле; ничего не сохранять.
- Пустое или состоящее из пробелов название запрещено. Не обрезать превышающий лимит текст молча.
- Сохранение закрывает окно только после успешной записи данных.
- Отмена без изменений закрывает окно. При изменениях закрытие по «Отмена», Escape или крестику требует выбора «Продолжить редактирование / Не сохранять».
- Щелчок по фону не закрывает форму.
- Двойной щелчок по сохранению не создаёт дубликат; на время операции кнопка блокируется.
- Если задача после сохранения не входит в текущую неделю или фильтр, показать уведомление «Задача сохранена» с действием «Показать». Оно открывает неделю задачи и переключает фильтр на «Все».

### 5.3. Статусы

Любой статус можно явно сменить на любой другой. «Отложено» не меняет дату и входит в число незавершённых задач.

При переходе в «Готово» запомнить прежний незавершённый статус и время завершения. При снятии отметки вернуть запомненный статус; если его нет, вернуть «Не начато». При явном выборе другого статуса использовать выбранный статус и очистить время завершения. Статус и отметка всегда синхронизированы.

Единственный источник состояния завершения — поле `status`; отдельного поля `isDone` нет. Флажок отображает `status === 'done'`. Редактирование названия или контекста готовой задачи не меняет `previousStatus` и `completedAt`. Повторная установка уже имеющегося статуса — пустая операция. Явный переход из «Готово» в незавершённый статус делает этот статус новым `previousStatus`; следующий переход в «Готово» запоминает его. Создание отдельной задачи сразу готовой устанавливает `previousStatus = 'todo'`.

### 5.4. Копирование

Действие «Копировать» открывает форму создания с названием, контекстом, датой, категорией и приоритетом исходной задачи. Новый статус — «Не начато», повторение выключено. Копия не связана с серией, не наследует историю переносов. Название сохраняется без добавления суффикса. Новый ID появляется только при сохранении.

### 5.5. Удаление и отмена

Обычное удаление одной задачи выполняется без предварительного подтверждения. Показать уведомление «Задача удалена» и кнопку «Отменить» на 10 секунд. Это правило заменяет подтверждение удаления из ранней концепции.

Удаление серии требует выбора области и подтверждения с пояснением, что будут удалены выбранный и будущие экземпляры. После него также доступна отмена.

Отмена восстанавливает удалённые задачи и данные серии, не откатывая другие изменения пользователя. Если было несколько удалений, хранить отдельные записи отмены с отдельными таймерами. Истёкшая запись удаляется; уведомления исчезают. Перезагрузка завершает возможность отмены, но само удаление остаётся сохранённым. Данные для отмены находятся только в памяти.

## 6. Порядок и перемещение

### 6.1. Ручной порядок

Новая задача помещается в конец выбранного дня. Карточки имеют отдельную ручку перетаскивания. Перетаскивание разрешено для любого статуса, включая «Готово».

Внутри дня перетаскивание меняет порядок. Между днями оно меняет дату и положение, сохраняя прочие поля. Показать место вставки и подсветку целевой колонки. Сброс вне допустимой области ничего не меняет. После успешного сброса сохранить результат.

При активном фильтре хранится единый порядок всех задач дня. Вставка перед видимой карточкой означает вставку перед ней в полном списке. Сброс в конец колонки означает вставку в конец полного списка, включая скрытые карточки. Порядок скрытых карточек относительно друг друга сохраняется.

При пагинации правило конца колонки по-прежнему означает конец полного дня; зону подписать «В конец дня». Для вставки на другую страницу использовать дату в редакторе и команды «Выше / Ниже»: они работают с соседней задачей отфильтрованного списка независимо от границы страницы. При пересечении границы открыть страницу перемещённой карточки и сохранить на ней фокус.

### 6.2. Сортировка

«Сначала важные» — разовая операция над всеми задачами каждого дня выбранной недели, независимо от фильтра. В подсказке указать «Упорядочить все задачи недели по приоритету».

Порядок: высокий, средний, низкий; внутри одинакового приоритета сохранить существующий порядок. Статус на сортировку не влияет. Результат сохранить как новый ручной порядок. Следующие добавления идут в конец; автоматической пересортировки нет.

### 6.3. Другие способы перемещения

Дата в редакторе позволяет отправить задачу на другую неделю. При изменении даты задача добавляется в конец нового дня. Добавить в меню карточки «Выше» и «Ниже» для управления порядком без мыши: обмен местами с соседней видимой карточкой; скрытые карточки остаются на своих позициях.

Любая смена даты добавляет запись истории: прежняя дата, новая дата, время операции и причина `manual` либо `rollover`. Исходная дата создания задачи не меняется.

После успешного перемещения озвучивать через отдельный `aria-live="polite"` регион: «Задача [название] перемещена: [день недели], [дата], позиция X из N». X и N относятся к полному списку дня в активной категории. Если карточка скрыта категорией, сообщить новую дату и «Не отображается при текущем фильтре». После сортировки сообщить «Задачи недели упорядочены по приоритету». При ошибке сохранения озвучить ошибку, а не успешное перемещение.

## 7. Повторения

### 7.1. Настройка

Единственный режим — «По выбранным дням недели». Можно выбрать от одного до семи дней. Выбор понедельника–пятницы эквивалентен будням, всех дней — ежедневному повторению; отдельных режимов для них нет. Ежемесячного повторения нет.

При включении повторения дата задачи становится датой начала серии. По умолчанию выбран день недели этой даты. Пользователь может снять его и выбрать другие дни: первый экземпляр тогда создаётся в ближайший выбранный день не ранее даты начала. Под формой показать вычисленную дату первого повторения.

Необязательная дата окончания включительна, не раньше начала. В заданном интервале должен существовать хотя бы один выбранный день, иначе ошибка. Без даты окончания серия действует до её прекращения пользователем в пределах поддерживаемого календаря.

Шаблон содержит название, контекст, категорию и приоритет. Статус не наследуется будущими экземплярами: каждый новый экземпляр начинается с «Не начато». При создании серии поле статуса фиксировано на «Не начато» с пояснением; изменить статус конкретного экземпляра можно после создания.

### 7.2. Генерация экземпляров

При загрузке, возврате во вкладку и переходе к неделе материализовать для каждой серии все подходящие даты от начала серии до максимума из воскресенья текущей недели и воскресенья просматриваемой недели, с учётом окончания серии. Будущие серии до наступления их периода не создают задач.

После перерыва восстановить все пропущенные экземпляры. Не отмечать их автоматически готовыми и не переносить без согласия. Вначале материализовать повторения, затем вычислить список переноса.

Каждая пара `(seriesId, scheduledDate)` уникальна. `scheduledDate` — исходная плановая дата повторения, она не меняется при переносах. Повторная загрузка, просмотр недели или перенос не создают второй экземпляр на ту же плановую дату. Все уже созданные будущие экземпляры сохраняются при возвращении к текущей неделе.

### 7.3. Изменения серии и одного экземпляра

При редактировании связанного экземпляра предложить область:

- «Только эту задачу»: менять название, контекст, категорию, приоритет, статус и фактическую дату; расписание недоступно. Изменения не затрагивают шаблон и другие экземпляры.
- «Эту и будущие»: менять шаблон, выбранные дни недели и окончание. Граница изменения — исходная `scheduledDate` выбранного экземпляра, даже если он перенесён. Поля статуса и фактической даты в этом режиме недоступны.

Для «Эту и будущие» разделить серию: старую закончить за день до границы; создать новую с отдельным ID и началом в день границы. Удалить старые экземпляры с `scheduledDate` не раньше границы и сформировать новые по новому шаблону до текущего горизонта. Новые экземпляры имеют статус «Не начато» и плановую дату без прежних переносов.

До применения явно предупредить: «Выбранное и будущие повторения будут созданы заново. Их отдельные изменения, переносы и статусы, включая “Готово”, будут сброшены». Показать число заменяемых существующих экземпляров. Требуется кнопка «Применить изменения»; отмена ничего не меняет. Экземпляры до границы остаются без изменений.

Отключение повторения в режиме «Эту и будущие» завершает старую серию перед границей, удаляет её экземпляры от границы и оставляет выбранный экземпляр как отдельную задачу с текущей датой и статусом. Предупредить об удалении будущих экземпляров.

Одиночную задачу можно превратить в серию через включение повторения в редакторе. После подтверждения «Задача будет заменена серией; новые повторения начнутся со статуса “Не начато”» удалить оригинал и создать серию с датой начала, равной его текущей дате. Вся операция атомарна.

### 7.4. Удаление и перемещение повторений

- «Только эту задачу»: удалить экземпляр и сохранить исключение `(seriesId, scheduledDate)`, чтобы генератор не восстановил его.
- «Эту и будущие»: закончить серию за день до `scheduledDate` выбранного экземпляра; удалить все её экземпляры от этой границы, независимо от текущих дат и статусов. Прошлые экземпляры сохранить.
- Отмена удаления восстанавливает и экземпляры, и прежнее расписание/исключение. Пока доступна отмена удаления части серии, изменения расписания той же серии блокируются с пояснением «Сначала отмените удаление или дождитесь окончания срока отмены».
- Перетаскивание, смена даты, быстрый выбор статуса и перенос на понедельник всегда затрагивают только один экземпляр, без запроса области.
- При совпадении фактических дат старого перенесённого и нового повторения показывать обе карточки. Не объединять их.

## 8. Перенос незавершённых задач

### 8.1. Условия

Кандидаты: все существующие задачи, у которых фактическая дата раньше понедельника текущей календарной недели и статус не `done`. Учитываются обе категории, любой приоритет, «Отложено» и повторения. Фильтр доски и просматриваемая неделя на список не влияют. Задачи более ранних дней текущей недели в него не входят.

Если есть кандидаты и окно ещё не показывалось автоматически в текущую неделю, показать его после загрузки и генерации повторений. Автопоказ — максимум один раз за календарную неделю. Сохранить неделю автопоказа при успешном открытии окна. Закрытие не переносит задачи и не означает согласие; ручная кнопка остаётся доступной всегда.

Если новая неделя наступила при открытой странице, проверить дату при возврате фокуса и раз в минуту. При открытом редакторе отложить окно до его закрытия. Не открывать два диалога одновременно. Просматриваемую неделю не переключать автоматически.

### 8.2. Окно

Заголовок «Перенести незавершённые задачи?», пояснение с точной датой понедельника назначения. Список отсортирован по фактической дате, затем по порядку внутри дня. Строка содержит флажок, название, дату, категорию, статус; у повторения — плановую дату.

По умолчанию выбраны все. Есть «Выбрать все», «Снять выбор», счётчик выбранных и кнопки «Подтвердить» / «Позже».

«Подтвердить» переносит выбранные задачи на понедельник текущей недели в конец списка этого дня в порядке окна. Сохраняются ID, статус, категория, приоритет, контекст и связь с серией. Записывается история. Невыбранные остаются на прежних датах. При нуле выбранных подтверждение просто закрывает окно; текст кнопки — «Оставить на прежних датах».

«Позже» и крестик закрывают окно без изменения задач. Повторный ручной вызов строит список заново. На следующей неделе оставшиеся задачи снова участвуют в автоматическом предложении. При отсутствии кандидатов ручная кнопка показывает «Незавершённых задач прошлых недель нет».

Перед подтверждением повторно проверить текущую дату. Если неделя уже изменилась, обновить дату назначения и список и потребовать новый щелчок подтверждения.

## 9. Фильтр и недельный прогресс

Фильтр только один: «Все / Работа / Личное». Он влияет на карточки, счётчики дней и прогресс. Не влияет на генерацию, перенос, экспорт и импорт.

Пусть N — число задач выбранной недели, удовлетворяющих категории, D — число этих задач со статусом «Готово». Прогресс = `Math.round(D / N * 100)`.

- При N = 0: пустая полоса, подпись «Пока нет задач», процент не выводится.
- При N > 0: процент и «Готово D из N».
- «Отложено» входит в N, но не в D.
- Все задачи равновесны независимо от приоритета.
- Удалённые задачи не учитываются.
- Любое изменение задачи немедленно пересчитывает показатели после успешного сохранения.
- Перенос изменяет состав обеих недель. Исторический процент не фиксируется отдельным снимком.

Примеры: 2 готовые задачи из 3 → 67%; 1 готовая и 1 отложенная → 50%; пустая неделя → «Пока нет задач».

## 10. Хранение, модель и целостность

### 10.1. Основной объект

Ключ localStorage: `my-week-planner.v1`. Значение — один JSON-объект:

| Поле | Тип и смысл |
| --- | --- |
| `schemaVersion` | Число `1` |
| `revision` | Неотрицательное целое, увеличивается при каждой успешной записи |
| `tasks` | Массив задач |
| `series` | Массив шаблонов повторений |
| `excludedOccurrences` | Массив исключений `{seriesId, scheduledDate}` |
| `settings` | `{categoryFilter: 'all' или 'work' или 'personal'}` |
| `meta` | `{lastAutoTransferPromptWeek: дата понедельника или null, backupReminderAfter: UTC timestamp или null}`; при отсутствии `backupReminderAfter` в старом файле версии 1 использовать null |

Поля задачи:

| Поле | Смысл |
| --- | --- |
| `id` | Уникальная непустая строка |
| `title`, `context` | Текст по ограничениям формы |
| `date` | Фактическая дата `YYYY-MM-DD` |
| `originalDate` | Дата при создании экземпляра, неизменяемая |
| `category` | `work` / `personal` |
| `priority` | `high` / `medium` / `low` |
| `status` | `todo` / `in_progress` / `deferred` / `done` |
| `previousStatus` | `todo` / `in_progress` / `deferred`; начальное значение `todo` |
| `completedAt` | ISO timestamp при статусе `done`, иначе null |
| `order` | Неотрицательное целое, позиция внутри даты |
| `seriesId` | ID серии либо null |
| `scheduledDate` | Плановая дата повторения либо null; для отдельной задачи оба поля связи null |
| `createdAt`, `updatedAt` | ISO timestamps |
| `moveHistory` | Массив `{fromDate, toDate, at, reason}` |

Поля серии: `id`, `title`, `context`, `category`, `priority`, `startDate`, `endDate` (дата либо null), `weekdays` (уникальные числа 1–7, где 1 — понедельник), `createdAt`, `updatedAt`.

Для остановленной до первого экземпляра серии допустимо `endDate < startDate`: это служебное представление прекращённой серии; генератор не создаёт её экземпляры. В пользовательской форме такое сочетание дат запрещено.

Не удалять шаблоны, на которые ссылаются сохранённые задачи. При разделении серии прошлые экземпляры продолжают ссылаться на старый ID. После изменения порядка нормализовать `order` до 0…N−1 для затронутых дат. При одинаковых значениях в импортированном файле использовать стабильный порядок массива и нормализовать его.

Генерировать ID через Web Crypto с проверкой доступности; не рассчитывать только на миллисекунды. Даты задач не переводить через UTC: использовать локальные компоненты календаря. ISO timestamps применяются только для времени действий. Переходы через конец месяца, високосные годы и смену часового пояса не должны сдвигать календарные даты задач.

Все timestamps (`createdAt`, `updatedAt`, `completedAt`, `moveHistory.at`, `exportedAt`, `backupReminderAfter`) хранить в UTC в формате `YYYY-MM-DDTHH:mm:ss.sssZ`. При показе времени действий допускается преобразование в текущий часовой пояс. Календарные строки `date`, `originalDate`, `scheduledDate`, границы серий и недели не преобразовывать в timestamps. Например, задача на `2026-10-19` остаётся на 19 октября и после переезда из Москвы в Токио. Меняется лишь вычисляемое «сегодня» по часам компьютера. Время выполнения задачи вроде «10:00» продуктом не предусмотрено.

### 10.2. Запись

Все операции выполняются над копией состояния: применить изменение, проверить целостность, сериализовать, записать одним `localStorage.setItem`, затем принять состояние и перерисовать интерфейс. Массовый перенос, изменение серии и импорт сохраняются одной записью. При ошибке не показывать частичный успех.

На старте проверить доступность хранения временным тестовым ключом с последующим удалением. При недоступности показать постоянное сообщение «Браузер не разрешает локальное сохранение. Изменения недоступны» и отключить изменяющие действия. Просмотр и экспорт доступных данных остаются возможны.

При переполнении или другой ошибке записи сохранить старое состояние, оставить введённый текст формы, показать «Не удалось сохранить данные. Экспортируйте копию и освободите место в хранилище браузера». Не очищать данные автоматически.

Если JSON повреждён или версия неизвестна, не заменять его пустым объектом. Показать экран восстановления: скачать исходное сохранение, импортировать корректную копию либо «Начать заново» с отдельным подтверждением удаления старого сохранения. Никаких автоматических миграций неизвестной версии.

### 10.3. Несколько вкладок

Совместная работа не поддерживается. Перед записью прочитать сохранённую `revision`; при несовпадении с загруженной версией отменить запись и предложить обновить данные. Слушать событие `storage`: обновлять интерфейс, если нет открытой изменённой формы; иначе показать предупреждение и сохранить ввод до решения пользователя. Безусловная перезапись чужой версии запрещена. Абсолютная транзакционная защита от одновременной записи двух вкладок не гарантируется localStorage; основной сценарий — одна вкладка.

### 10.4. Контроль объёма и ручная очистка

В «Хранилище и очистка» показывать приблизительный размер сохранения: `2 * (key.length + serializedState.length)` байт, переведённый в MiB. Это оценка UTF-16, а не известный браузерный лимит. Не показывать выдуманный процент свободной квоты. При оценке от 3 MiB показывать неблокирующее предупреждение «Данных стало много. Сохраните копию и при необходимости удалите старые готовые задачи». Фактическая ошибка записи возможна и раньше; её обработка остаётся обязательной.

Предоставить очистку только готовых задач с фактической датой раньше выбранной границы. По умолчанию граница — сегодняшняя дата минус шесть календарных месяцев, с ограничением дня последним днём месяца назначения. Предварительно показать границу, число удаляемых задач и оценку освобождаемого места. Незавершённые задачи не удалять, независимо от возраста. Старые задачи автоматически не удалять и не архивировать в том же localStorage: такой архив не освобождает место.

Перед очисткой предложить экспорт, затем отдельную кнопку «Удалить N готовых задач» с пояснением, что отмена доступна только через импорт резервной копии. При активных таймерах отмены обычного удаления очистку блокировать до их завершения либо отмены пользователем. Удалять атомарно. Для удаляемых повторений сохранять компактное исключение `(seriesId, scheduledDate)`, чтобы генерация не восстановила их. Если итоговая оценка не меньше исходной, не выполнять очистку и сообщить, что выбранная операция не освободит место. После очистки исторический прогресс пересчитывается по оставшимся задачам.

Генератор повторений сохраняет пакет целиком только после успешной записи. При нехватке места не терять прежние задачи и не запускать тот же неудачный пакет автоматически на каждом событии фокуса. Показать «Не удалось создать повторения: недостаточно места», оставить доступ к экспорту и очистке, предложить «Повторить» после освобождения места. До успешного повтора не предлагать перенос по неполному набору повторений. Очистка может не освободить достаточно места; не обещать бесконечное хранение.

## 11. Экспорт и импорт

### 11.1. Экспорт

Скачать UTF-8 JSON с отступами, содержащий `format: 'my-week-planner'`, `exportedAt` и `data` — весь объект хранения. Имя: `my-week-backup-YYYY-MM-DD-HHmmss.json` по локальному времени. Экспорт включает все недели, серии, исключения и настройки, независимо от фильтра; не включает временные формы и таймеры отмены.

### 11.2. Импорт

1. Выбрать один `.json` файл, максимум 10 MiB. Неподходящее расширение, превышение размера или ошибка чтения дают понятное сообщение.
2. Разобрать JSON и проверить `format`, версию и все поля данных. Проверить перечисления, типы, длины, реальные даты, уникальность ID и пар повторений, существование связанных серий, согласованность null-полей. Исключение и существующий экземпляр одной пары одновременно недопустимы. Неизвестные поля игнорировать; строить новый объект только из разрешённых полей.
3. При любой ошибке отклонить весь файл с указанием причины. Не менять текущие данные частично.
4. Показать число задач и серий и предупреждение «Импорт полностью заменит данные в этом браузере».
5. Предложить «Скачать текущую копию». Это отдельное действие; пользователь может продолжить без копии. Не утверждать, что скачанный файл уже сохранён пользователем на диске.
6. Кнопки «Заменить данные» / «Отмена». После подтверждения выполнить атомарную запись, назначив новую локальную `revision`, а не доверяя импортированной.
7. При успехе очистить таймеры отмены, открыть текущую неделю, восстановить импортированный фильтр, материализовать повторения и при необходимости предложить перенос. При ошибке записи оставить исходные данные.

### 11.3. Строгая проверка и безопасное отображение

Проверять файл по явной схеме раздела 10.1 с учётом единственного необязательного поля `backupReminderAfter`. Обязательные поля нельзя молча заменять начальными значениями; не преобразовывать строки в числа или логические значения. `revision` и `order` — безопасные целые, даты — действительные календарные даты в разрешённом диапазоне, timestamps — строгий UTC-формат. `id` и `seriesId` — строки длиной 1–128 из ASCII-букв, цифр, `_` и `-`; новые ID генерировать в этом же формате. Проверить тип каждого объекта и массива, элементы истории, значения `reason` (`manual` / `rollover`), границы `weekdays` и отсутствие повторов в исключениях. `completedAt` обязателен и не null только для `done`; `previousStatus` не может быть `done`.

На любой глубине отклонять ключи `__proto__`, `prototype`, `constructor`; ограничить глубину JSON 12 уровнями. Для защиты от чрезмерных структур установить пределы: 20 000 задач, 2 000 серий, 50 000 исключений и 1 000 записей истории на задачу. Эти пределы также проверяются при локальных изменениях и генерации; превышение отклоняет операцию с понятным сообщением, без обрезки данных. Размер 10 MiB ограничивает входной файл, но не гарантирует его размещение в localStorage.

Использовать только `JSON.parse`, никогда `eval` или `Function`. Копировать проверенные поля явно, без слияния произвольных объектов. Пользовательские строки выводить через `textContent` и `value`; не подставлять их в HTML, обработчики событий, стили, URL или CSS-селекторы. Имена классов выбирать из фиксированных перечислений. DOM-ID формировать независимо от названий задач; ссылки на объекты держать в Map или замыканиях. Эти правила применяются и к данным из localStorage, а не только к импорту.

### 11.4. Напоминание о резервной копии

При наличии данных и `backupReminderAfter = null` показать неблокирующее предложение «Сохраните резервную копию». После запуска скачивания экспорта установить следующую дату напоминания через семь суток; это означает только запуск скачивания, а не подтверждённое сохранение файла на диске. «Напомнить позже» откладывает напоминание на сутки. Проверять срок при открытии и возврате во вкладку; если срок наступил, показывать одну компактную плашку с «Экспортировать» / «Напомнить позже», без модального окна. Пустое хранилище не требует напоминания. Автоматических скачиваний и фоновых действий при закрытой странице нет. Ошибка сохранения даты напоминания не отменяет уже запущенное скачивание и обрабатывается как ошибка записи настроек.

## 12. Визуальный стиль и доступность

Светлый спокойный интерфейс. Тёмной темы и кислотных цветов нет.

| Элемент | Цвет |
| --- | --- |
| Фон | `#F6F7F4` |
| Карточки и формы | `#FFFFFF` |
| Основной текст | `#28332F` |
| Второстепенный текст | `#627069` |
| Границы | `#DDE4DE` |
| Работа: текст / подложка | `#496F9A` / `#EAF0F8` |
| Личное: текст / подложка | `#47745B` / `#EAF3EC` |
| Высокий приоритет: текст / подложка | `#89621D` / `#FAF1DE` |

- Системный шрифт `Segoe UI, Arial, sans-serif`, основной размер 14–16 px.
- Отступы кратны 4 px; карточки со скруглением 10–12 px, тонкими границами и лёгкой тенью.
- Минимальная ширина колонки — 170 px. Основные проверки при 1366×768 и 1920×1080; при 1024 px ширины доступна прокрутка доски без обрезания кнопок.
- Диалоги шириной до 560 px, окно переноса до 760 px; максимальная высота 85vh, внутренний скролл содержимого.
- Цвет всегда сопровождается текстом; приоритет не заменяет цвет категории.
- Все кнопки имеют доступные имена, поля — связанные подписи. Видимый фокус, логичный Tab-порядок, управление кнопками Enter/Space.
- Модальные окна удерживают фокус, после закрытия возвращают его к вызвавшему элементу. Ошибки и уведомления доступны через `aria-live`.
- Анимации до 150 ms; учитывать `prefers-reduced-motion`.
- Не вставлять пользовательский текст через `innerHTML`; использовать текстовые DOM-свойства.

## 14. Проверки и критерии приёмки

### 14.1. Функциональные проверки

Все UC-01–UC-41 должны соответствовать описанным результатам. Схожие сценарии сохраняются отдельными проверками, поскольку проверяют разные исходы и регрессии. Дополнительно проверить:

- 0 из 0, 0 из 3, 2 из 3, 3 из 3; ожидаются пустое состояние, 0%, 67%, 100%.
- Смена категории готовой задачи корректно меняет показатели активного фильтра.
- Отложенная задача участвует в переносе и знаменателе прогресса.
- Перенос повторения на уже занятый день не удаляет другой экземпляр и не создаёт дубликат исходного.
- Граница изменения серии определяется плановой, а не фактической датой.
- Исключённое повторение не восстанавливается после импорта и последующей генерации.
- Перетаскивание при фильтре не теряет скрытые задачи.
- Несколько удалений и отмен не откатывают другие правки.
- Ошибка localStorage во время массовой операции оставляет прежнее состояние целиком.
- Нажатие кнопки сохранения несколько раз не создаёт несколько задач.
- Редактирование контекста готовой задачи не меняет запомненный статус; снятие отметки возвращает именно его.
- Отмена очистки и ошибка её записи не удаляют ни одной задачи. Удалённое очисткой повторение не возникает после перезагрузки.
- Переход через границу месяца при вычислении шести месяцев не создаёт несуществующую дату.
- Счётчики и «Выбрать все» работают по полному набору при постраничном выводе.
- Ошибка генерации оставляет сохранённые задачи доступными, не вызывает бесконечных попыток и не запускает перенос неполного набора.
- При достижении пределов структуры операция отклоняется без потери данных; экспорт остаётся доступен.

### 14.2. Календарь и данные

Проверить неделю через 31 декабря, високосное 29 февраля, воскресенье/понедельник, смену месяца и локального времени. Проверить пустой JSON, неправильную версию, повторяющиеся ID, отсутствующие серии, несуществующие даты, превышение лимита текста, неподдерживаемые статусы, слишком большой файл и HTML в названии. HTML должен отображаться как текст и не исполняться.

Для переноса использовать фиксируемую в тестах текущую дату, а не ожидать наступления понедельника. Чистые функции дат, прогресса, генерации, разделения серии и валидации должны быть отделены от DOM внутри `script.js`, чтобы их можно было проверять независимо.

### 14.3. Визуальная и эксплуатационная проверка

Проверить всю матрицу браузеров раздела 2.1 на `file://`: первое открытие, запись, перезагрузка, закрытие и повторный запуск, перетаскивание, клавиатуру, скачивание и импорт. Для Safari использовать macOS; проверка только Chromium не заменяет Firefox и Safari. Особенность localStorage для локальных файлов зависит от браузера; факт успешного сохранения должен быть проверен, а не предположен. При недоступности соблюдать раздел 10, не поднимать сервер автоматически. Недоступные для проверки браузеры перечислить как непроверенные; полную кроссбраузерную приёмку до их проверки не объявлять.

Проверить обе целевые ширины, длинные названия, пустые состояния, 30 карточек в одном дне, переполнение диалога, клавиатурное управление и отсутствие ошибок консоли. Проверить 2 000 задач и 50 серий: обычная операция должна давать видимый результат в пределах 300 ms на тестовом компьютере; первичная обработка — в пределах 2 секунд. Если обработка длится дольше, показать индикатор занятости, исключить повторный запуск операции и зафиксировать измерения в отчёте реализации.

Провести два отдельных нагрузочных сценария: 2 000 задач, распределённых по разным неделям, и 2 000 задач в одном дне. Во втором сценарии в DOM присутствуют максимум 50 карточек этого дня, но прогресс и операции учитывают все задачи. Проверить длительную историю повторений, предупреждение от 3 MiB, отказ записи и восстановление работы после очистки. Наличие индикатора занятости не отменяет необходимости исследовать превышение целевых времён.

Готовность подтверждается тремя рабочими файлами, отсутствием внешних сетевых зависимостей, пройденными сценариями и кратким отчётом о браузерах и выполненных проверках. Тестовые материалы не являются дополнительными файлами поставки приложения.

## 15. Что не входит в первую версию

Аккаунты, пароли, роли, общий доступ, сервер, синхронизация устройств, почта, push-уведомления, напоминания по времени, интеграции, вложения, подзадачи, почасовой календарь, поиск, пользовательские категории, тёмная тема, мобильный интерфейс, ежемесячные повторения, автоматическое объединение задач и неизменяемые отчёты прошлых недель.

Пока страница закрыта, приложение не выполняет код. Очистка данных браузера может удалить сохранение; перенос папки или открытие другим браузером не обеспечивает перенос данных. Для этого предназначен экспорт/импорт JSON.
